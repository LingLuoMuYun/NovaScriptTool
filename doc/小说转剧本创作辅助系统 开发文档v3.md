## 一、系统概述

NovaScriptTool 是一款 AI 驱动的小说转剧本创作辅助系统。通过 4 个专业化 AI Agent 的异步流水线协作，将小说文本自动转化为结构化 YAML 剧本。同时提供人工干预工具链（场景锁定、行内评论、版本管理、依赖图谱、增量重算），实现"AI 提效 + 编剧掌控"的协作模式。

## 二、数据库设计

### ER 模型 (7 张表)

```prisma
Novel (小说)
  ├── id, title, content, status, analysis
  ├── Character[]      (1:N) 角色
  ├── Scene[]          (1:N) 场景
  ├── Annotation[]     (1:N) 注记
  ├── DependencyEdge[] (1:N) 依赖关系
  └── ChatConversation[](1:N) 聊天会话

Character (角色)
  ├── id, name, aliases, roleType, traits (JSON)
  └── novelId → Novel

Scene (场景)
  ├── id, sceneNum, location, timeOfDay
  ├── isLocked, lockedBy
  ├── currentVersionId → Script
  ├── novelId → Novel
  └── Script[]         (1:N) 剧本版本

Script (剧本版本)
  ├── id, yamlContent, version
  ├── createdBy (system/user)
  ├── parentVersionId → Script (版本链)
  ├── sceneId → Scene
  └── Scene[]          (1:N) 当前版本引用

Annotation (注记)
  ├── id, targetType (scene/character/line)
  ├── targetId, content, type (note/todo/question/suggestion)
  ├── resolved, authorName, blockIndex
  └── novelId → Novel

DependencyEdge (场景依赖)
  ├── id, sourceSceneNum, targetSceneNum
  ├── dependencyType (causal/character/timeline)
  ├── weight (0-1)
  └── novelId → Novel

ChatConversation (AI 对话会话)
  ├── id, title, mode (general/template), status
  ├── novelId → Novel (可选)
  └── ChatMessage[]    (1:N) 消息

ChatMessage (对话消息)
  ├── id, role (user/assistant), content
  └── conversationId → ChatConversation
```

## 五、核心功能实现

### 5.1 多 Agent 分析流水线

4 个 Agent 协作的流水线，支持 SSE 实时进度推送：

- **Agent 1（剧情解构者）**：提取大纲（起因/发展/高潮/结局）、时间线、冲突
- **Agent 2（角色图谱构建师）**：提取角色姓名/别名/身份/性格/目标/人际关系
- **Agent 3（场记统筹）**：切分场景（编号/地点/时间/室内外/角色/摘要）
- **Agent 4（剧本主笔）**：生成结构化剧本（Action/Dialogue/Transition）

每步有进度回调（stage/progress/message/stats），前端 SSE 实时渲染。

### 5.2 长文本分块分析

对于 >15,000 字或 >5 章的小说，自动启用滑动窗口分块：

1. `splitChapters()` 识别章节（支持"第X章"/"Chapter X" 模式）
2. 构建滑动窗口（≤12,000 字/窗，1 章重叠）
3. 逐窗分析（上文角色 + 关键事件作为 window context）
4. 去重合并（同名 + 别名 + 模糊匹配 >0.8）
5. 安全降级（内容拦截时截取前 5000 字重试）

### 5.3 依赖图谱与增量重算

- `buildDeps()`: AI 分析场景间因果/角色/时序依赖，存储为加权有向边
- `analyzeImpact()`: BFS 遍历计算最小受影响范围
- `incrementalPipeline()`: 仅重算受影响场景（锁定场景自动排除）
- 前端：ImpactDialog 展示影响路径 + 重算确认

### 5.4 行内评论系统

Google Docs 风格评论功能（ScriptViewer + AnnotationPanel）：

- **块级锚定**：`targetId = "{sceneId}:{blockIndex}"`
- **@ 提及**：`MentionInput` 组件，正则检测 `@` 触发过滤下拉，箭头键导航
- **评论类型**：笔记(note) / 待办(todo) / 疑问(question) / 建议(suggestion)
- **状态管理**：resolved 字段，视觉区分已解决/未解决
- **上下文**：hover 显示 💬 按钮，已评论块黄色高亮

### 5.5 版本管理

- **版本链**：每次修改创建新 Script 记录（version 递增，parentVersionId 链）
- **Diff 引擎**：`diffYaml()` 解析 YAML 为 content 数组，逐元素对比
- **回滚**：复制目标版本为新版本（保留审计链），更新 Scene.currentVersionId

### 5.6 AI 写作助手

- **模板系统**：8 套风格（古装/都市/悬疑/科幻/奇幻/历史/言情/通用），每套独立的 system prompt + temperature + 角色偏好
- **会话管理**：ChatConversation/ChatMessage 持久化，自动加载最近会话
- **上下文注入**：关联小说时自动注入原文片段（前 3000 字）+ 角色列表
- **引擎切换**：从 Mimo（SSE 流式）→ DeepSeek（JSON 非流式），解决 buffering 卡死问题

### 5.7 暗色模式

- Tailwind `darkMode: 'class'` 策略
- `ThemeProvider` Context + `localStorage` 持久化
- `prefers-color-scheme: dark` 自动检测
- 21 个组件全量适配（sed 批量 + 手动修复）
- 色彩映射：`bg-white→dark:bg-gray-900` / `text-gray-700→dark:text-gray-200` 等

### 5.8 Electron 桌面应用

- 主进程管理 Express + Next.js 子进程生命周期
- IPC 桥接：原生文件对话框（打开小说/导出剧本）
- 数据库自动迁移（生产模式 `prisma migrate deploy`）
- 跨平台打包（Windows NSIS / macOS DMG / Linux AppImage）
