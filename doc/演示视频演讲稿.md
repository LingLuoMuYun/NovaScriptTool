## 🎬 第一段：开场（1.0 min）

**【画面】** 展示项目 README 首页或 GitHub 仓库页，镜头慢慢推进标题。

> 大家好，今天我来给大家演示一个我独立开发的开源项目——**NovaScriptTool**，一款 AI 驱动的小说转剧本创作辅助系统。

**【画面】** 切到 Bilibili 视频封面或项目 Logo（如果有的话）。

> 它的核心功能是：**你给它一部小说，它用 4 个专业 AI Agent 自动协作，帮你完成从剧情分析、角色提取、场景划分到剧本生成的全流程**，最终产出符合影视工业标准的 YAML、Final Draft 或 Fountain 格式的结构化剧本。

**【画面】** 切到系统架构图或 Agent 流水线示意图（可以画一个简单的 4 Agent 流程图）。

> 四个 Agent 分别是：
> - Agent 1「剧情解构者」：提取故事大纲、时间线和冲突
> - Agent 2「角色图谱构建师」：提取角色身份、性格、关系和语言风格
> - Agent 3「场记统筹」：将故事切分为可拍摄的场景
> - Agent 4「剧本主笔」：为每个场景撰写结构化对白和动作描述

> 而且这个过程全部**自动化**，你只需要上传小说、点一个按钮，剩下的交给 AI。

**【画面】** 切到实际运行界面首页。

> 好，话不多说，我们直接上 Demo。

**【画面】** 展示首页 `localhost:3000` —— 标题、上传区、小说列表。

> 这是系统首页。你可以通过两种方式上传小说——**拖拽上传 TXT 文件**，或者**直接粘贴文本**。系统会自动检测文本编码，包括 Windows 上常见的中文 GBK 编码，不需要你手动转码。

**【操作】** 演示拖拽一个 `.txt` 小说文件到上传区。

> 上传成功后，它会对文本进行预处理——清洗空行、统一标点、切片分章——然后显示字数统计和预估章节数。这里显示我的小说大约 5 万字，分了 15 章。

**【画面】** 展示小说出现在下方列表中。

## 🎬 第三段：一键流水线（2.0 min）

**【画面】** 切到小说详情页（`novels/[id]`），展示标题、状态徽章、操作按钮区。

> 这是小说详情页。顶部分别是：标题、字数、创建时间、当前状态。下面是一排操作按钮，核心就是这个紫色的——**「一键生成（分析 + 剧本）」**。

**【操作】** 鼠标悬停在按钮上。

> 点击之后，系统会依次执行 4 个 Agent，整个过程大约需要 1-2 分钟。这里有一个很重要的设计——**分析缓存**。

**【画面】** 指向缓存状态徽章。

> 如果你已经分析过这本小说，且内容没有改动，系统会自动跳过 Agent 1 和 2，直接进入剧本生成阶段，省掉 70% 的时间。只有当你修改了原文，才会触发重新分析。

**【操作】** 点击「一键生成」按钮。

**【画面】** 展示 PipelineProgress 进度条和实时消息。

> 点击后，你会看到**实时进度可视化**。这是通过 SSE 流式推送实现的——后端每完成一步，就向前端推送一条进度事件，包括当前阶段、百分比、场景编号等。你可以看到：
>
> - 「Agent 1: 正在解构剧情…」
> - 「Agent 2: 正在提取角色…」
> - 「Agent 3: 正在规划场景…」
> - 「Agent 4: 正在撰写场景剧本…（逐个场景推进）」

**【画面】** 等待流水线完成，展示「✅ 全部完成！」。

> 好了，流水线完成。一共提取了 8 个角色，划分了 12 个场景。我们来看看结果。

## 🎬 第四段：分析结果展示（1.5 min）

**【画面】** 切换到「分析」Tab。

> 先看「分析」Tab。这里展示了 Agent 1 和 Agent 2 的产出。

**【操作】** 展示 PlotOutline 组件——大纲四段（起因/发展/高潮/结局）。

> 这是**故事大纲**——起因、发展、高潮、结局四个阶段，AI 自动从原文提炼。

**【操作】** 向下滚动，展示时间线。

> 这是**全局时间线**——按照故事时间顺序排列的关键事件节点。每个节点包含：事件简述、所在章节、时间提示、地点、参与角色、搜索关键词。这些关键词可以直接用于全文搜索。

**【操作】** 展示冲突列表。

> 这是**剧情冲突分析**——系统会自动识别人物冲突、内心冲突等类型。注意这里有一个特殊处理：**系统会过滤掉 AI 幻觉生成的抽象概念**（比如“命运”、“社会”这些不是具体人物的冲突参与方），只保留原文中有姓名的角色。

**【操作】** 切换到「角色」Tab。

> 再看「角色」Tab。每个角色都有详细档案：姓名、别名、身份背景、性格标签、核心目标、行为动机、人际关系网。

**【操作】** 点击展开一个角色的详情。

> 特别提一下——这是 **「人设实验室」**（CharacterLab）。你可以在这里为每个角色配置**语言风格包**：语气、用词习惯、方言口音、口头禅、句长偏好。这些配置会注入到 Agent 4 的 Prompt 中，确保每个角色的对白有独特的说话方式，杜绝「千人一面」的问题。

## 🎬 第五段：剧本查看与编辑（2.0 min）

**【画面】** 切换到「场景」Tab。

> 现在看最重要的部分——**剧本**。「场景」Tab 列出了所有场景，每个场景显示编号、地点、时间、出场角色。

**【操作】** 点击一个场景，展示 ScriptViewer。

> 点击一个场景，右侧会展开**结构化剧本查看器**。这不是纯文本——每个内容块都是独立的数据对象：动作描述渲染为段落、对白渲染为角色名+情绪+台词、转场指令渲染为特殊样式。

**【操作】** 悬停在某个内容块上，展示评论按钮。

> 每个内容块都支持 **Google Docs 风格的行内评论**。你可以悬停出现 💬 按钮，添加评论。评论支持 @ 提及角色（会自动补全角色名）、四种类型（笔记/待办/疑问/建议）、已解决/未解决状态切换。

**【操作】** 切换到 ScriptBlockEditor。

> 对于不熟悉 JSON 格式的编剧，我们提供了 **「块编辑器」**（ScriptBlockEditor）。它把每个 action/dialogue/transition 渲染为可视化的卡片——蓝色是动作、绿色是对白、紫色是转场。你可以直接在这里添加、删除、编辑块，不需要面对大括号和引号。

**【操作】** 展示右上角的校验指示灯。

> 注意右上角的校验指示灯——🟢 全部通过、🟡 有警告、🔴 有错误。它会实时告诉你当前剧本的质量状态。

**【操作】** 如果有 DualPaneEditor，切过去展示。

> 还有一个**双栏编辑器**——左边是源码 JSON，右边是可视化块编辑器。两边实时同步，适合技术用户和非技术用户协作。

## 🎬 第六段：Schema 校验（1.0 min）

**【画面】** 点击操作栏的「🔍 校验剧本」按钮。

> 刚才提到的校验指示灯，它的后端是一套**三层校验体系**。

**【操作】** 展示 ValidationPanel 弹出。

> 点击「校验剧本」，弹出完整的校验报告面板。

> - **Layer 1 结构校验**：基于 Zod Schema，检查所有必需字段是否存在、类型是否正确。
> - **Layer 2 语义校验**：7 条业务规则——比如「场景结尾必须有转场指令」（R001）、「对白角色必须在出场列表中声明」（R002）、「连续 3 个同类型块警告」（R004）等。每条规则分为 error 和 warning 两个级别。
> - **Layer 3 跨场景校验**：检查跨场景的一致性问题，比如多个连续场景地点频繁切换。

**【操作】** 展开一个有问题的场景，展示具体的 issue 卡片。

> 每个问题都包含：规则编号、严重度、错误路径、中文描述、**修复建议**。点击「跳转」按钮可以直接定位到对应场景进行编辑。

## 🎬 第七段：角色关系网络图（0.5 min）

**【画面】** 切换到分析仪表板或直接展示 CharacterNetworkGraph。

> 分析 Tab 里还有一个**角色关系网络图**，基于 `react-force-graph-2d` 构建。

**【操作】** 展示力导向图的交互。

> 节点大小根据**度中心性**（角色与多少其他角色有连线）动态调整——核心人物更大。支持：
> - **搜索聚焦**：输入角色名，高亮相关子图
> - **节点拖拽**：自由调整布局
> - **多关系边捆绑**：如果 A 和 B 之间有多重关系，合并为一条粗边
> - **点击节点**：右侧弹出详情面板，显示该角色的所有关系
> - **PNG 导出**：一键保存为高清图片

## 🎬 第八段：AI 写作助手（1.0 min）

**【画面】** 切换到「AI 助手」Tab，展示 ChatPanel。

> 小说详情页右侧还有一个**内置 AI 写作助手**，基于 DeepSeek API。

**【操作】** 输入一个问题。

> 你可以直接向 AI 提问，比如「张三这个人物的性格弧线怎么设计？」。注意这是**真 SSE 流式输出**——每个 token 实时到达，逐字显示，不是等完整回复后一次性渲染。

**【画面】** 展示模板选择器。

> 助手内置了 **8 套编剧风格模板**——古装、都市、悬疑、科幻、奇幻、历史、言情、通用。每套模板是独立的 system prompt + temperature 配置。切换到古装模板后，AI 会自动用古装剧的编剧思维来回答。

**【画面】** 展示上下文注入（角色列表、原文片段自动加载）。

> 当助手关联了当前小说，它会自动获取角色列表和原文前 3000 字作为上下文——你不需要每次手动粘贴。

## 🎬 第九段：多格式导出（0.5 min）

**【画面】** 点击「📥 导出剧本」下拉菜单。

> 系统支持三种格式导出：

**【操作】** 分别展示三种格式的下载结果。

> - **YAML**：结构化的人类可读格式，保留完整语义标注，适合存档和二次处理。
> - **Final Draft (.fdx)**：专业编剧软件 Final Draft 的原生格式，可以直接导入。
> - **Fountain**：纯文本剧本标记语言，广泛兼容各种编剧工具。

> 导出引擎会自动检测剧本内容格式——结构化 JSON 正常导出，旧格式自由文本尽力而为降级处理。

## 🎬 第十段：其他亮点（1.5 min）

**【画面】** 快速过一遍其他功能。

> 时间有限，我再快速展示几个亮点功能：

**【操作】** 展示依赖图谱操作——点击「构建依赖图」→ ImpactDialog。

> **依赖图谱与增量重算**：系统会分析场景之间的因果关系（因果、角色、时序），构建有向图。当你修改了某个角色设定或场景内容后，点「增量重算」，系统会用 BFS 算法计算最小受影响范围，只重新生成受影响的场景。锁定的场景自动保护，不会被覆盖。

**【操作】** 展示版本历史。

> **版本管理**：每次 AI 生成或手动编辑都会创建新版本，不覆盖历史。支持任意两个版本的逐块 Diff 对比和无损回滚。

**【操作】** 按 Ctrl+K 唤起全局搜索。

> **全文搜索**：基于 SQLite FTS5 引擎，跨小说、剧本、角色、注记四维检索，BM25 相关性排序，⌘K 全局弹窗实时过滤。

**【操作】** 展示暗色模式切换。

> **暗色模式**：全局适配，localStorage 持久化偏好，自动检测系统主题。

**【操作】** 展示 QueueStatusPanel（如果有排队任务）。

> **并发控制**：内置令牌桶速率限制器 + FIFO 任务队列，多用户同时操作时不会打爆 API。

## 🎬 第十一段：结尾（1.0 min）

**【画面】** 切回项目 README 或 GitHub 页。

> 总结一下。NovaScriptTool 解决的核心问题是：**将非结构化的长篇小说，通过 4 个专业化 AI Agent 的协作，转化为严格符合影视工业标准的结构化剧本**。

**【画面】** 展示技术栈徽章（Next.js / TypeScript / Express / Prisma / TailwindCSS / Electron）。
