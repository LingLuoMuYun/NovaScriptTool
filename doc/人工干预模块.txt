8. 核心优化模块：人机协作的“编剧干预层”
8.1 优化背景与设计哲学
原系统设计围绕“多 Agent 自动化流水线”展开，在效率层面实现了质的飞跃。然而，在真实的影视剧本创作工业流程中，编剧的核心价值并非被动接受生成结果，而在于持续的判断、调整与艺术性打磨。全自动化的“黑盒”模式容易导致两个致命问题：

不可控性：Agent 基于概率的修改可能破坏编剧已认可的优秀设计。

低协作性：任何微调都需重新运行复杂工作流，打断创作心流。

因此，本优化模块的核心理念是：将系统从“替代编剧”转变为“增强型智能副驾”。在保持自动化高效的同时，建立一套完整的编剧主导、AI 辅助的协作契约，将人工干预能力作为一等公民集成到系统架构中。

8.2 功能架构与实现思路
本干预层通过引入“锁定状态机”、“版本快照系统”及“依赖感知的增量重算引擎”三大核心组件，实现对现有 Agent 工作流的深度增强。

核心组件 1: 场景级锁定与注记系统 (Scene Locking & Annotation System)

职责：赋予编剧对剧本元素的最终裁决权，并作为知识沉淀载体。

实现思路：

锁定状态机：为 Scene 和 Script 表增加 is_locked (Boolean) 和 locked_by (User ID) 字段。在 Agent 调度层增加全局前置过滤器：当 Agent 试图更新任何场景内容前，必须检查该场景的锁定状态。若 is_locked == true，则跳过所有写操作，并触发系统日志记录。
结构化注记：设计独立的 Annotation 实体模型，通过 target_type (Scene/Line/Character) 和 target_id 实现多态关联。注记内容支持 Markdown 格式，并可标记 type (Enum: 待办, 疑问, 灵感, 警示) 和 resolved 状态。
UI 协同：在前端双栏工作台中，锁定场景将显示灰色锁定遮罩与解锁按钮；注记则以侧边栏气泡形式展示，并支持@提及其他协作用户。
核心组件 2: 版本快照与差异可视化引擎 (Version Snapshot & Diff Engine)

职责：提供完整的剧本演化历史，支持无损回溯与变更审计。

实现思路：

快照策略：改造 Script 表，将 version 字段升级为主键之一。每次 Agent 生成新结果或编剧手动保存时，系统不覆盖旧记录，而是插入一条带有递增 version 和新 created_at 时间戳的新记录。当前活跃版本由 Scene 表中的 current_version_id 外键指向。
可视化差异：在后端封装 DiffService，利用 jsdiff 或 patience diff 算法，对两个版本的 YAML 字符串进行语义化比对。输出结果需包含：新增/删除/修改的动作行、对白行、角色标签等。
回滚机制：前端在展示任一历史版本时，提供“恢复为此版本”按钮。后端执行回滚时，本质是复制目标版本的 yaml_content 作为一条全新记录插入，并将 Scene.current_version_id 指向这个新记录（而非直接修改指针，以保证审计链完整）。
核心组件 3: 依赖感知的增量重算引擎 (Dependency-Aware Incremental Recalculation Engine)

职责：实现精准、高效的局部剧本重写，避免不必要的全局资源消耗。

实现思路：

构建依赖图谱：在项目初始化或每次全量生成后，由 DependencyGraphBuilder 模块分析并存储各场景之间的弱依赖关系。主要依赖类型包括：同一角色的连续出场、因果事件的跨场景关联（例如“发现线索” → “前往地点B”）。
影响域分析：当编剧触发重跑（修改了角色设定或某段原文），前端需明确指定“修改影响范围”（例如：“仅角色‘张三’的性格标签”，“场景 3 的对白”）。后端 ImpactAnalyzer 接收此信息，在依赖图谱中执行广度优先搜索（BFS），计算出一个最小影响场景集合（Minimal Impact Set）。
工作流动态裁剪：将此最小影响集合传递给 AI 调度层的多 Agent 协同网络。Agent 1、2 仍可运行以提供上下文，但 Agent 3、4 仅对集合内的场景重新生成 scene_num 和 YAML 内容。对于未受影响且未锁定的场景，保持原样不动，并在前端向用户明确高亮显示“重新生成的场景区域”。
8.3 数据库实体扩展 (Schema Additions)
为支持上述功能，需对原数据模型进行如下扩展：

数据表名	字段定义说明	核心作用与关联关系
Annotation (注记表)	id (UUID, PK)
novel_id (FK)
target_type (Enum)
target_id (UUID)
author_id (FK)
content (Text)
type (Enum)
resolved (Boolean)	多态关联到场景、台词行或角色。实现了创作思路的可视化沉淀与任务追踪。
Scene (扩展字段)	is_locked (Boolean)
locked_by (UUID, FK -> User)
current_version_id (UUID, FK -> Script)	增加锁定状态控制与当前活跃版本指针。
Script (重构为版本表)	id (UUID, PK)

8.4 优化后的典型工作流
初版生成：系统全量运行多 Agent 工作流，生成剧本初稿。所有场景默认为 解锁 状态。

编剧审阅与干预：

编剧发现场景 5 的对话非常满意，右键点击场景头选择 “锁定”。is_locked 设置为 true。

编剧对场景 8 的对白不满意，添加注记：“需加强主角的犹豫心理”。

精准修改与重跑：

编剧在角色图谱侧边栏中，将“主角”的性格标签从“果断”改为“优柔寡断”。

系统弹出提示：“检测到角色变更，可能影响场景 4、7、8、9。是否仅重新生成这些场景？” 编剧确认。

增量重算引擎计算影响域，仅将场景 4、7、8、9 重新送入 Agent 3 和 Agent 4。场景 5 因处于锁定状态，被自动排除在重算队列之外。

版本对比与决策：

编剧查看重算后的场景 8，认为旧版本更好。

打开该场景的版本历史面板，进行 Diff 可视化对比。

点击“恢复到此版本”，系统自动将旧版本内容作为新版本（version+1）插入，并设为当前版本。

成果产出：编剧确认所有场景后，导出包含所有注记与最终版本的完整剧本包。

通过引入这一干预层，系统从一个“令人惊艳的自动化演示工具”，真正进化为一个能够融入专业编剧日常创作闭环的可靠伙伴。它在不牺牲自动化的前提下，赋予了创作者前所未有的控制力、安全感和协作便利性。
